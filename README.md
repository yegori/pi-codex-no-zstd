# pi-codex-no-zstd

Глобальное расширение [Pi](https://pi.dev), обходящее **зависящие от zstd-сжатия** ошибки Codex HTTP/SSE:

```json
{"detail":"Bad Request"}
```

**Это обход конкретного воспроизведённого сбоя, а не исправление всех HTTP 400.** Проект не связан с OpenAI или разработчиками Pi.

English: Pi extension that sends Codex HTTP/SSE request bodies as plain JSON, preserving the original JSON bytes, authentication and routed fetch. It works around compression-dependent opaque HTTP 400 errors. Not a general fix for every “Bad Request”. Installation and rollback commands below work on Windows, macOS and Linux with a compatible Pi/Node runtime; only Windows has been integration-tested.

## Установка

Требуются Pi и Node.js 24+. Проверенная конфигурация: Pi **1.5.2**, Node **24.18.0**, Windows; отдельно проверена совместимость с **pi-proxy-router 1.2.4**. Совместимость с другими версиями не гарантируется.

```sh
pi install git:github.com/yegori/pi-codex-no-zstd@v1.0.0
```

Это глобальная установка для текущего agent directory. В уже открытом сеансе выполнить `/reload` **в момент простоя**, либо перезапустить Pi. Новые сеансы подхватывают пакет автоматически.

Авторизация остаётся обычной авторизацией Pi. Если Codex ещё не подключён, выполнить `/login` и выбрать провайдера OpenAI/ChatGPT, затем модель через `/model`. Пакет не содержит и не переносит учётные данные; для установки публичного репозитория вход в GitHub не нужен.

Для проверки в самом Pi:

```text
/codex-transport
```

Команда показывает, загружен ли обход, и количество преобразованных запросов текущего runtime. Нулевой счётчик нормален до первого HTTP/SSE-запроса Codex или при использовании другого провайдера/WebSocket.

**Не устанавливайте вторую копию**, если раньше вручную клали расширение в `~/.pi/agent/extensions/codex-no-zstd/`: сначала переместите прежнюю папку целиком за пределы каталога `extensions`, затем установите пакет и выполните reload.

Установка выше закреплена за тегом `v1.0.0`. Чтобы следить за веткой разработки вместо фиксированного релиза:

Pi считает эти источники одним git-пакетом, а не двумя независимыми установками. Ветка может меняться; для воспроизводимой установки предпочтителен тег.

### Локальная разработка

```sh
git clone https://github.com/yegori/pi-codex-no-zstd.git
cd pi-codex-no-zstd
npm run check
npm test
pi install .
```

`npm install` для тестов и локальной установки **не нужен**: runtime-зависимостей нет, host-пакеты предоставляет Pi. Не устанавливайте отдельную копию Pi AI в пакет — это может создать дублирующиеся реестры.

## Почему это помогает

В контролируемом тесте одинаковый synthetic JSON размером 140 212 байт через один и тот же Pi, аккаунт, модель и прокси дал:

| Передача | Результат |
|---|---|
| zstd level 3, 206 байт по сети, без обхода | HTTP 400, `{"detail":"Bad Request"}` |
| те же распакованные JSON-байты, с обходом | HTTP 200, завершённый ответ `OK` |

Похожие A/B-наблюдения, включая Pi и текстовые запросы: [openai/codex#60594](https://github.com/openai/codex/issues/60594). Ни универсальный предел размера, ни конкретный неисправный серверный компонент этим не установлены. Длинная история, картинки и превышение контекста — не обязательные условия: тест выше не содержит изображений, инструментов или истории.

## Что меняется

1. Пакет регистрирует штатный native provider `openai-codex` с обёрткой `stream` и `streamSimple`.
2. Для API `openai-codex-responses` оборачивается переданный `options.fetch` (или стандартный fetch, если своего нет).
3. Только у запросов с `Content-Encoding: zstd` на путь, оканчивающийся `/codex/responses`, body распаковывается непосредственно перед отправкой.
4. Удаляются `Content-Encoding` и устаревший `Content-Length`; отправляются исходные распакованные байты **без JSON.parse/JSON.stringify**.

OAuth, обновление токенов, модельный каталог, стандартные наложения `models.json`, прокси-маршрут, AbortSignal и поток ответа остаются штатными. Расширение не повторяет модельные запросы или инструменты, не меняет историю и не патчит установленные файлы Pi, `globalThis.fetch` или `node:zlib`.

В Pi 1.5.2 сжатие внутри провайдера всё ещё происходит, затем этот пакет распаковывает body на границе fetch. Это обход, а не устранение лишнего CPU/памяти; сетевой трафик становится больше. Если upstream добавит штатное отключение сжатия, оно предпочтительнее.

### Область действия и ограничения

- Только Codex HTTP/SSE. WebSocket и другие провайдеры/API не меняются; принудительно переключать transport пакет не пытается.
- Фабричная native-регистрация происходит до `session_start`, поэтому текущий `pi-proxy-router` оборачивает уже исправленный провайдер и передаёт ему свой routed fetch. Установка proxy-router для работы пакета не обязательна.
- Иное расширение, заменяющее native provider `openai-codex`, может конфликтовать. Композиция с произвольными сторонними регистрациями не гарантируется.
- Распаковка ограничена **512 MiB на запрос**. Неизвестный тип body/ошибка распаковки останавливают отправку с короткой локальной ошибкой. Проверка отмены выполняется до/после асинхронной распаковки; сам worker распаковки не прерывается.
- Ошибки параметров, невалидные изображения, переполнение контекста, авторизация и сетевые отказы этим не исправляются.
- `--no-extensions` отключает пакет. Другой `PI_CODING_AGENT_DIR`, пользователь, компьютер или WSL-профиль требуют отдельной установки.
- `features.enable_request_compression=false` в `~/.codex/config.toml` — настройка **Codex CLI**, не этого Pi provider.

## Проверки

```sh
npm run check
npm test
```

14 локальных тестов без сети, токенов и зависимости от Pi проверяют байтовую идентичность JSON/Unicode, заголовки, исходные объекты, AbortSignal, отсутствие retries, passthrough, Request/ArrayBuffer/views, обёртку провайдера и прокси-композицию. GitHub Actions запускает эти проверки без секретов.

Для **необязательной живой проверки** сначала установить пакет и авторизовать Codex в Pi:

```sh
pi --offline --no-context-files --no-skills --no-prompt-templates --no-mcp --no-tools --no-session --model openai-codex/gpt-6.1-sol -e ./test/live-probe.ts -p "/codex-synthetic-probe"
```

Она отправляет один synthetic prompt выбранной модели через обычную авторизацию Pi и может расходовать лимит подписки/токены. `--offline` запрещает стартовые обновления, **не** сам запрос модели. Проектные файлы не читаются; ответ должен завершиться `OK`, HTTP 200. Live-тест не запускается через `npm test` или CI. В Git Bash для slash-команды может понадобиться префикс `MSYS2_ARG_CONV_EXCL='/codex-synthetic-probe'`.

Также при первоначальной установке проверен полный агентный цикл: один synthetic tool result с Unicode и корректным PNG, затем завершённый ответ модели; оба HTTP-запроса получили 200. Обезличенный отчёт: [VALIDATION.md](VALIDATION.md).

## Безопасность

Расширения Pi выполняются с правами пользователя. Ознакомьтесь с исходниками перед установкой.

Пакет не хранит OAuth/API-ключи, не пишет запросы/историю в логи и не запускает фоновые процессы. Счётчики `/codex-transport` живут только в памяти. Не прикладывайте к issue `auth.json`, заголовки Authorization, приватные документы, скриншоты или полные transcript/payload. Для сообщения о проблеме достаточно версий, transport, обезличенного результата синтетического теста и описания других provider-расширений.
